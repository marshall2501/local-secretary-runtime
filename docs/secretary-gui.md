# Secretary GUI — 依頼・判断経過・証拠・回答（実験版）

## 概要

2026-09-27、最初の操作可能なローカルGUIを
scripts/secretary/secretary_gui.py に追加しました。
Python製 NiceGUI 3.17.1 を使用し、既存のSecretary Core / LangGraphを
実際に呼び出します。見た目だけのモックではなく、ブラウザから依頼を
受け、既存のcheckpointへ記録し、実際のOllama処理中に経過を更新します。

依頼本文・対象・領域・モデル、実行状態、統括役の判断、専門担当への指示、
Python側の結果検証、回答案の独立監査、資料の出典・未検証・模擬・
対象未紐付けフラグ、最終回答を表示します。

ローカルTask IDで再開。過去依頼もローカルcheckpointから復元します。

## 全文コピーできる検証用ログ（2026-09-27追加・サブPC未検証）

ユーザーの実機試験で、複数ターンの判断と証拠がスクリーンショットに
収まりきらないことが判明。各Task詳細の「取得した証拠」の**一番下**に
「検証用ログ（全文コピー）」を追加しました。閲覧向けのカード表示は維持します。

- コピー用テキスト欄：Task ID、元の依頼、対象・モード・モデル・状態、最新の
  追加情報・保留質問、保存済みの判断・委任・評価・監査・ユーザー回答の**全件**
  （内部イベントJSONを含む）、過去・現在の取得資料の**全件**
  （M1/M2/R1/R2、検索条件・出典・模擬・未検証・対象未紐付け、元レコードJSONを含む）、
  最終回答・残課題・実行エラーを出力。意図的な件数・文字数切捨てはありません。
- 「ログ全文をコピー」：ブラウザのクリップボードに1操作でコピー。
- 「詳細JSON」を開くとcheckpoint内部状態の完全なJSONを別欄に表示し、
  「JSON全文をコピー」からそのままコピーできます。
- 処理中のcheckpoint更新や依頼切替でも、同じ画面のテキスト出力を再生成します。
- 将来のTaskでは、統括役が質問した**原文**と、監査に却下された回答**原案**も
  判断イベントに残します。旧checkpointの過去質問の原文等、
  当時そもそも保存されていなかった情報を遡及的に復元するものではありません。
  旧Taskのcheckpointに残った最後の質問は表示可能です。
- イベントごとの発生時刻は現checkpointにないため、番号順で表示します。
  個々の日時があるように見せかけることはしません。

個人情報を含む可能性があるため、**実記憶モードでコピーした全文を外部共有する際は、

GitHubへ勝手に送信しません。コピーボタンは閲覧中のブラウザだけを操作します。

## 2026-09-27：コピーした全履歴で見つかった未完了判定を修正（新コード未実機検証）

初回の全文コピー機能はサブPCブラウザから**18件のイベント・3回の観測を含む旧Taskログを取得しチャットで解析できた**。旧Taskは、CPU/GPU負荷と再起動後再発をユーザーから受領後に記憶担当がM1/M2を取得したものの、統括役が既に回答された負荷・再起動情報を再び「必要」とする理由を出し、回答監査は「現時点で原因を確定できない」という暫定報告を妥当として承認した際、**元の依頼「原因不明という報告だけで調査を終了しない」まで満たしたと誤判定**。Coreは Task をansweredとして閉じてしまっていた。これは証拠の真偽の監査と、ユーザーが依頼した業務目的の達成が混同されていた不具合。

現在の実験ブランチでは、明示的に継続を求める依頼（例：「調査を続けて」「不明という報告だけで終了しない」）に限り、**独立回答監査のsupported=trueを業務完了の根拠にしない**Pythonの目的ゲートを追加。実際の外部検証結果がない場合、暫定報告（latest_report）を記録したまま waiting_user とし、未提出のログや新しい検証結果を求める具体的な質問、または追加調査手段についての相談へ進む。単なる現状説明で依頼を閉じない。証拠検証と目標達成を別の判定として記録する。

GUIでは回答待ちTaskに「現時点の報告（依頼は未完了）」を表示し、以前の実装で回答済み扱いとなった明示的な継続依頼に限り「未解決の依頼として調査を続ける」ボタンを表示。クリックしたときだけ、古いTask IDとすべての観測・履歴を維持して reopen し、今回の実行予算を再設定する。過去の記憶や重複資料は消さない。新しいイベント goal_gate / task_reopened を全文ログにも掲載。一般の一問一答の answered は従来どおり終了し、再開操作の対象外。

制限：当面のゲートは日本語の明示的な継続表現を認識する限定実装で、一般の自然言語意図を完璧に理解するものではない。外部実測に基づく自動目標達成判定はまだ実装していない。架空fixtureには有効な実測を返す操作がないため、実際に原因が解明されたと保証せず追加情報待ちとなる。既に answered の古いTaskを無断で書き換えない。利用者がGUI上で明示的に再開したときだけ切り替わる。新しい回帰テスト4件を追加し、従来20件＋追加4件＝**24件予定**だが新コードのサブPCテストとブラウザ確認はまだ実施していない。


## 2026-09-27：本人回答の丸写し質問を停止し、証拠不足を区別する

25件のオフライン試験はサブPCで全件成功。しかし同一Taskを再開した実Qwen3は「過去に類似症状なし・対策未実施・新しいログ未取得」という最新の本人回答を一字一句そのまま次の質問に転記した。判断理由も既回答のPC負荷・再起動情報を必要としていた。単に全回答をManagerに渡すだけでは判断品質を保証できないことが判明。イベント22（本人回答）→23（本人回答の丸写しを質問）→24（waiting_user）の実測を根拠とする。

実験ブランチへ質問のPython側の検査を追加した。質問案が空・極端に短い、本人の既回答と同じ、回答後に同じ質問を再提示、または質問・情報依頼の形式を満たさない場合は却下し、question_rejectedイベントへ候補と理由を記録する。この軽量検査は日本語質問の意味や既回答との間接的な重複を完全に判定するものではない。

まだ情報源を調べていないTaskでは不正な質問文を安全な一般質問へ差し替える。記憶と資料の両方が取得済みの架空fixture Taskでは、同じ架空資料から新しい独立証拠が得られないのでblocked_capability（情報源の接続待ち）へ移し、未完了の元依頼・全履歴・暫定報告を保存して、必要な実情報源や読み取り専用診断ツールが未接続であることを表示する。目的完了を装わない。旧checkpointが既に本人回答を質問として保存している場合、GUIに「無効な質問を取り消し、情報源不足として保留」を表示し、ユーザーがクリックした時だけ同じTaskのまま誤った質問を取り消す。情報源の接続機能・blocked Taskの自動再開はまだ未実装。

Core回帰テスト3件とGUI回帰テスト1件を追加。従来25件＋4件＝29件予定。GitHub反映のみでサブPCの新テストと画面操作は未実証。次は稼働中GUI停止→隔離worktreeのpull→29件試験→GUI再起動→旧Taskの情報源待ちへ移行を各1操作ずつ確認。継続的な架空問答を重ねるより、実情報源・実診断手段の接続を次の能力として優先する。
